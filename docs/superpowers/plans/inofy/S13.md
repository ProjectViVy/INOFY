**Goal:** Ship a reproducible Go App with embedded frontend while proving the root library and both host integrations satisfy the v0.1 gates.

**Architecture:** Asset build packages S10 studio into S09 Go server with `embed`; release verification runs each module/repo's existing gates and real browser/host scenarios. Artifacts declare schema/catalog/compiler/Eino identity; no remote publication by this Story.

**Tech Stack:** Go (CGO_ENABLED=0), pnpm, existing host CI, browser acceptance runner selected in S10.

## Global Constraints

- Editor present in first release; Go server/binary independent of Node.js at runtime; root import independent of App.
- Do not claim release with missing G1–G11 evidence. External release/repository publication needs explicit authorization.
- Benchmark report separates compile, pure run, parallel effect, representative Garden payload and storage write costs without inventing targets.

## Review Focus

- Fresh App binary serves built assets on a host with Node unavailable (Task 1).
- An independent consumer imports root under CGO_ENABLED=0 without SQL drivers (Task 1).
- Reopening a waiting run after App restart resumes only from exact committed checkpoint (Task 2).
- Real ViVy and Garden paths remain within native authority/size budgets (Task 2).
- Release metadata rejects incompatible schema/catalog/engine identity instead of silently running (Task 1).
