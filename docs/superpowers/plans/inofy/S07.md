# S07 — Reusable Draft and Publication Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Definitions can be saved with CAS, validated against a frozen catalog, published immutably and admitted by exact revision.

**Architecture:** Optional `definitions.Service` operates on INOFY `Artifact` with a small transactional repository contract; storage authority remains with each host. No App/database dependency enters core.

**Tech Stack:** Go, standard library; S02 normalization and S03 catalog compiler.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§4.3–4.4, 6; [index](index.md).

## Global Constraints

- One draft per workflow, immutable increasing integer published revisions, exact used catalog identity; same artifact publication is idempotent.
- `latest` resolves once at admission; archived workflow disallows new runs but retains referenced revisions.
- Host implementations must atomically persist draft ETag CAS and revision allocation; library supplies no DDL.

## Review Focus

- Two editors saving stale ETags produce one success and one `revision_conflict` (Task 1).
- Concurrent publish cannot allocate duplicate revision or changed used catalog identity (Task 2).
- Layout-only edits change artifact digest but not semantic DefinitionDigest (Task 1).
- Repeated publish of same artifact returns existing revision with no new row (Task 2).
- An archived definition's referenced revision remains readable but cannot admit new run (Task 2).

### Task 1: Draft CAS contract

**Files:** Create proposed `definitions/service.go`, `repository.go`, `service_test.go`, `memory_test.go` (in-memory fake only, not production authority).

**Interfaces:** Consumes root `Artifact`, `Catalog`, `Diagnostic`; produces `Service.SaveDraft(ctx, workflowID string, expectedETag string, a Artifact) (Draft,error)`, `Service.ValidateDraft(ctx, workflowID, expectedETag string, c Catalog) ([]Diagnostic,error)`; repository `UpdateDraftCAS(ctx, workflowID, expectedETag string, a Artifact) (Draft,error)` and `GetDraft(ctx,workflowID string) (Draft,error)`. Workflow creation uses explicit absent ETag sentinel in repository.

- [ ] Implement service delegating CAS to repository transaction; normalize/validate once per update; preserve incoming presentation unknown fields and return durable ETag.

### Task 2: Immutable publication

**Files:** Create proposed `definitions/publish.go`, `publish_test.go`; extend `repository.go` with atomic publication method and bounded listing/query.

**Interfaces:** Produces `Service.Publish(ctx, workflowID, expectedETag string, c Catalog) (Revision,error)`, `Service.GetRevision(ctx, workflowID string, revision uint64) (Revision,error)`, `Service.List(ctx, cursor string, limit int) (Page,error)`; repository `PublishCAS(ctx, workflowID, expectedETag string, rev Revision) (Revision,error)` allocates revision transactionally. Revision stores artifact, semantic/artifact/used-catalog digests and exact node IDs/impl IDs.

- [ ] Write `TestPublishIdentity` for same artifact idempotency, changed catalog impl requires new publication, dual publish CAS, archival and immutable old revision.
- [ ] Run `go test ./definitions -run TestPublishIdentity -count=1 -v`; expect FAIL.
- [ ] Validate exact draft ETag/catalog snapshot, require trusted authority check at host admission, delegate monotone revision+dedup transaction to repository, expose immutable read.
- [ ] Rerun focused/full root tests; expect PASS; return repository transaction contract for S08/S11.

**Acceptance / rollback:** G1/G9 concurrent publication evidence; rollback must preserve published revisions referenced by runs. Never make a mutable draft the lookup key of a running Program.
