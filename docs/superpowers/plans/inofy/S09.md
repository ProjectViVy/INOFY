# S09 — Authenticated App API and Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local user can author, publish and execute real model/wait nodes through authenticated HTTP with committed event inspection.

**Architecture:** The App Go module binds S07 definitions, S08 SQLite and dispatch to authenticated `/api/v1` handlers; EinoExt-backed model adapter resolves secrets from host bindings. SSE projects committed redacted events only.

**Tech Stack:** Go `net/http`, EinoExt model component selected against pinned Eino, pure-Go SQLite App module.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§5.2, 11.3–11.4; [index](index.md).

## Global Constraints

- Loopback default, owner token in user-only file or configured token file; HttpOnly SameSite session, Origin/CSRF check on mutations, bearer support for CLI.
- API routes and error envelope exactly architecture §11.4; stable cursor-paginated lists and run events; no secrets in definition/event/SSE/checkpoint.
- Catalog supports pure value/template, one working OpenAI-compatible EinoExt model binding and human wait; provider identity fixed at admission. Model timeout unknown unless provider reconciles.

## Review Focus

- An unauthenticated direct output GET and cross-origin mutation reject without leaking values (Task 1).
- Slow SSE subscriber disconnects with recoverable cursor while a run commits (Task 2).
- Draft test snapshots exact ETag; later edit cannot change admitted run (Task 2).
- Missing provider credentials fail before effect without echoing secrets (Task 3).
- Ambiguous provider timeout classifies unknown and is not retried/billed again blindly (Task 3).
