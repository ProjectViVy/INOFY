# S03 — Eino DAG, Switch and Select Compiler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A validated DAG including structured conditional regions compiles to Eino and executes once through the library facade.

**Architecture:** Eino owns readiness/branch activation; compiler maps predecessor packets by ID and resolves JSON Pointers in wrappers. Explicit select receives the one active candidate, and all active exits attach to END.

**Tech Stack:** Go; Eino compose `v0.9.13`; `jsonschema/v6` through S02.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§5.1–5.3, 7.1–7.3; [index](index.md).

## Global Constraints

- No authored cycles outside repeat, no custom ready queue, no implicit data edges, no cross-region activation.
- Use `WithNoDirectDependency` for root/ancestor data of gated calls; ordinary predecessors are AND.
- Public `Program` immutable; exact Eino build and used descriptor IDs bind ProgramDigest.

## Review Focus

- Missing node output pointer returns `binding_missing` without coercing null (Task 1).
- Two independent exit effects must finish before success even if output binding finishes earlier (Task 1).
- Nested switch inside one port must not leak packets across sibling regions (Task 2).
- Zero/multiple select candidates produce diagnostics or runtime errors, never arrival-order selection (Task 2).
- External caller gets no Eino-dependent public types (Task 1).
