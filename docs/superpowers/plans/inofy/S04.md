# S04 — Bounded Repeat Container Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A serial repeat with one inline DAG body executes safely through Eino, preserving explicit state, typed output and iteration identity.

**Architecture:** Compile repeat into an Eino cyclic Graph with a Workflow body; Eino handles graph scheduling, while a serializable controller packet checks `until`, iteration and a defensive max-step bound.

**Tech Stack:** Go; pinned Eino `v0.9.13` Graph/Workflow APIs.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§5.4, 7–8; [index](index.md).

## Global Constraints

- Exactly one nesting level, default max 8 iterations, at least one iteration; reaching limit without `until=true` yields `iteration_limit`.
- Each iteration uses `container/zero-based-iteration/node`; retry does not change its logical key; no cross-scope references except `initial`.
- Do not hold leaf effect permits in container callbacks; do not invent recursive workflow invocation.

## Review Focus

- A zero iteration cap rejects at compile time instead of succeeding (Task 1).
- At cap with false predicate, return `iteration_limit` or an explicitly declared schema-valid fallback (Task 1).
- Body with a switch converges before evaluating until; inactive branches never copy stale state (Task 2).
- Cancellation during iteration stops new work and preserves completed attempt evidence (Task 2).
- Two repeat iterations have distinct operation keys while a retry in one keeps its key (Task 2).
