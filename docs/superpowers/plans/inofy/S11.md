# S11 — ViVy Runtime and Studio Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ViVy's existing bounded task DAG runs via INOFY while retaining native authority, child runs, Journal/checkpoints and unchanged normal delegation; reusable definitions can use the same adapter.

**Architecture:** Only ViVy's `internal/runtime` imports executable INOFY; the adapter converts a validated descriptor and maps calls to existing `WorkflowNodeRunner`/`runWorkflowNode`. ViVy owns storage and exposes its backend RPC/event contract through the existing UI/module lifecycle; S10 supplies the TypeScript transport and shared editor.

**Tech Stack:** Go, ViVy current Go module, SQLite/PostgreSQL parity, existing ViVy Studio UI bridge.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§9, 15 G7; [index](index.md). Verified baseline `83d6610545a8831937b2d351176353008881446b`; read `../agent-vivy/AGENTS.md` and scoped rules before edits.

## Global Constraints

- Preserve `StartWorkflow` immutable revision/admission, existing descriptor limits and tool narrowing, `Service.Run`, Journal and generation/session identity; editor never grants authority.
- Atomic visibility for separate blob/Journal: durable immutable checkpoint blob first, authoritative reference/projection manifest transaction second; orphan blobs may be GC'd, missing referenced bytes never exposed.
- `WorkflowNodeRunner` is currently `func(context.Context, WorkflowNodeRequest) (string,error)`; no mandatory App, definition service or Studio for ordinary delegation.

## Review Focus

- Existing read-only parallel DAG gives same outputs/cancel behavior and stable child IDs after migration (Task 1).
- Journal commit failure after an effect yields recovery_required, never false success (Task 2).
- Blob persists then manifest fails: orphan blob cannot be resumed; manifest never points at missing blob (Task 2).
- Approval resume with wrong parent/session/generation rejects; duplicate operation key does not create second child (Task 2).
- Disabling reusable product/Studio does not break normal delegated task runs (Task 3).
