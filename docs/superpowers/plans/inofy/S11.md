Use superpowers:executing-plans or subagent-driven-development; apply test-driven-development and verification-before-completion. Checkboxes track future work, not completed evidence.

**Goal:** VIVY uses INOFY as its only task-graph engine while retaining native Run/session/policy/Journal/storage ownership. In this delivery cycle, reusable Definition drafts/publications and an INOFY editor integrated into VIVY `ui/` also reach their separate host acceptance gates.

**Architecture:** [VIVY detailed cutover design](https://github.com/ProjectViVy/agent-vivy/blob/docs/issue23-inofy-cutover-plan/docs/superpowers/specs/2026-09-29-inofy-cutover-design.md) and [issue #23](https://github.com/ProjectViVy/agent-vivy/issues/23). The former descriptor translation plan is retired. New graphs use only `inofy.workflow/v1`; the VIVY runtime implements NodeExecutor and RunStore around native one-shot children and a Core Storage transaction. The INOFY App SQL/HTTP service is not a VIVY dependency. The VIVY UI Module supplies the host transport for INOFY's shared editor.

**Tech stack:** INOFY Go library and Studio TypeScript; VIVY Go, SQLite/PostgreSQL, `@vivy/ui-sdk` action client, selected Recipe UI Module.

**State:** Planned on `docs/s11-vivy-cutover-plan`; no implementation or passing integration evidence. S01–S10 are recorded Done in the [INOFY index](index.md), subject to fresh-head verification. S12 Garden remains independently tracked. VIVY plan branch is `docs/issue23-inofy-cutover-plan`.

### INOFY-owned enabling task A

**Files:** Inspect `definition.go` and schema source; add a small root exported schema accessor (proposed `schema_export.go`) and tests. Confirm exact signature against current head. `DefinitionSchema() json.RawMessage` is proposed, with defensive copy. It must expose the same strict executable schema as INOFY's decoder, not duplicate validation logic. Host node catalog and limits remain VIVY-owned.

- [ ] Write agreement/immutability tests for valid, invalid, unknown-property, wrong-version and binding cases.
- [ ] Run focused `go test ./... -run 'Definition|Schema' -count=1` and record expected failure.
- [ ] Implement the accessor from canonical schema data; keep `DecodeArtifact` and semantic validation authoritative.
- [ ] Run focused tests and `go test ./...`; record actual results and commit SHA before VIVY pins the change.

The existing `studio/src/vivy-transport.ts` provides a host bridge interface, not a live VIVY backend. If G requires a narrow transport change, test it in INOFY and pin the resulting commit in VIVY. Do not add a competing Studio shell or credential store. VIVY's full executable tasks and acceptance evidence are kept in the linked index to avoid two diverging plans.

**Review focus:** One schema grammar, one graph engine, native VIVY authority, atomic RunStore, non-replayable child effects, and honest capabilities. Any unsupported storage primitive or failure in both-driver parity blocks production switching; no checkboxes are pre-approved.
