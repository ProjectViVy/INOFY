# S01 — Public Contracts and Pinned Eino Proofs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An external Go module can import the INOFY contracts, and executable probes settle the Eino features on which the compiler depends.

**Architecture:** The root module exports data-only contracts with no App/SQL import. Targeted conformance fixtures run against `github.com/cloudwego/eino v0.9.13` and must report the actual module version and API behavior before downstream Stories are released.

**Tech Stack:** Go, Eino compose v0.9.13, Go standard library.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§3, 6–8, 15; index [status/dependencies](index.md). Source baseline INOFY `2085d7b2feffec03ee7775c78d697ed3e8fb3cba`, Eino tag `v0.9.13` / `c5e6aef927cca02bea934541f8dff2ea711b2ca7`.

## Global Constraints

- Proposed module `github.com/ProjectViVy/inofy`, to be confirmed before publishing. No `apps/`, SQL, network client or listener imports in root; initialization has no I/O effects.
- Public `Compile`, `Program.Run`, `Bindings`, `NodeExecutor`, `RunStore` signatures are exactly architecture §6; no Eino type crosses them.
- Canonical definition version `inofy.workflow/v1`, normalizer `inofy-normal-v1`; v0.1 defaults and limits in architecture §7.4.

## Review Focus

- Missing Go toolchain must produce a clearly recorded blocked probe, never fake green results (Task 2).
- An inactive Eino branch must neither activate its node nor satisfy another branch's AND dependency (Task 2).
- A non-triggering root-data mapping must not bypass a switch gate (Task 2).
- Multiple addressed waits and resumed inner Graph branches must retain address identity (Task 3).
- Module import from an unrelated Go consumer must avoid SQL/App transitive dependencies (Task 1).
