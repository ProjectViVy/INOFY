# S10 — Reusable Visual Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One browser editor authors the shared Definition, saves/reopens it without semantic drift, tests and publishes, and inspects/waits/resumes on real runs in the App and ViVy shell.

**Architecture:** A transport-first TypeScript package renders React Flow as a projection of the semantic schema and separate layout. App HTTP and ViVy host adapters implement the same `StudioTransport`; backend diagnostics/digests are authoritative.

**Tech Stack:** TypeScript, React, React Flow ecosystem (`@xyflow/react` candidate version pinned during setup), pnpm, browser test harness selected and pinned by this Story.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §§4, 11.4, 12; [index](index.md).

## Global Constraints

- Semantic schema `inofy.workflow/v1`, server digest only, editable layout outside semantic Definition; unknown types visibly unresolved and unpublishable.
- en/zh labels, keyboard selection/deletion/undo, accessible forms, zoom/fit, draft/published/run-snapshot distinction in first release.
- Browser does not hold owner token/long-lived credentials in localStorage; transport handles authenticated session.

## Review Focus

- Unknown imported node survives save/reopen yet publication blocks with diagnostic (Task 1).
- Browser numeric unsafe integer fixture remains string or receives server error without silent rounding (Task 1).
- Stale ETag save leaves dirty state and exposes conflict (Task 2).
- SSE disconnect/replay restores authoritative statuses without inventing skipped nodes (Task 2).
- Multiple wait prompts require complete answers and display redacted server text only (Task 2).
