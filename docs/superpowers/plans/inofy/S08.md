# S08 — Standalone SQLite Authority and Dispatch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-process App persists definitions, admissions, event commits, protected outputs and waits across restart without replaying unknown effects.

**Architecture:** The App has a separate Go module with pure-Go SQLite, embedded migrations and a durable run table. Bounded in-memory dispatch merely wakes admitted runs; SQLite is the sole App authority.

**Tech Stack:** Go; `modernc.org/sqlite` candidate (version must be pinned/verified for CGO=0); Eino transitively from root module.

**Spec:** [architecture](../../specs/2026-09-28-inofy-architecture.md) §11.1–11.2 and §8; [index](index.md).

## Global Constraints

- Separate App module; root embedding has no SQL driver. Single state-directory owner, migrations run explicitly at App start, loopback default at S09.
- Run tables/unique keys exactly architecture §11.2; one SQL transaction makes `RunStore.Commit` identity/events/projection/checkpoint visible.
- 4 active runs and 32 pending admissions by default; running on restart -> recovery_required; waiting stays quiescent; admitted never-started can dispatch.

## Review Focus

- Start commit failure leaves zero provider calls (Task 1).
- Same CommitID/body gives original receipt; changed body yields `idempotency_conflict` (Task 1).
- Two concurrent resume writers leave one winner, no duplicate effect (Task 1).
- Crash between persisted admission and wakeup dispatches once at restart (Task 2).
- Archived definition cannot cascade-delete a run's revision/checkpoint/output (Task 1).
